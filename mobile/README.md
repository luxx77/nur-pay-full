# Nur Pay — мобильное приложение

eWallet: переводы между пользователями и приём платежей торговой точкой
по QR. Приложение работает **на настоящем бэкенде** из `../backend`:
деньги, история и балансы приходят оттуда, состояние держат BLoC-кубиты.

## Запуск

Сначала поднимите бэкенд (`cd ../backend && make db-up && make migrate-up
&& make run`), потом приложение:

```bash
# Android-эмулятор: 10.0.2.2 — это localhost хоста, адрес по умолчанию
flutter run
```

Адрес бэкенда держим в `.env` (копия `.env.example`, в гит не попадает).
Приложение само читает его при старте (`dotenv.load()` в `main.dart`,
подключён как asset) — никакой флаг запуска не нужен:

```bash
cp .env.example .env   # один раз, потом править адрес в .env
flutter run             # .env подхватится сам
```

На настоящем устройстве в `.env` ставьте IP компьютера в локальной сети
(не `localhost` — это будет сам телефон):

```
NURPAY_API_URL=http://10.110.12.117:8080
```

Если меняете `.env` на лету, перезапустите `flutter run` — hot reload
файл не перечитывает.

Флаги `--dart-define` / `--dart-define-from-file=.env` по-прежнему
работают и имеют приоритет над `.env`-файлом — пригодится для CI/сборок
без ассетов.

Приложение открывается с ввода номера. Кода из SMS на сервере нет —
экран оставлен как шаг сценария, вход происходит по кнопке «Tassykla».
Дальше PIN набирается дважды: он локальный, хранится в защищённом
хранилище устройства и сервер о нём не знает.

Режим определяется сервером: мерчант — это пользователь с `type =
merchant` в базе. Переключателя в приложении нет, вкладки и цветовая
схема следуют за ролью из сессии.

## Как устроено

```
core/network/      ApiClient на dio, единый разбор ошибок {code, message}
core/session/      сессия и PIN в защищённом хранилище устройства
features/wallet/   domain (сущности, интерфейс репозитория) + data (DTO,
                   datasource, реализация) — общий слой для всех экранов
features/*/presentation/bloc/   кубиты: сессия, кошелёк, перевод,
                   пополнение, приём оплаты, платёжный QR
```

Экраны знают только интерфейсы из `domain`: `WalletRepository` и
`AuthRepository` раздаются через `RepositoryProvider` в `app/di.dart`.
Взяты кубиты, а не полные блоки с событиями: событий у этих экранов
ровно столько же, сколько методов, и лишний слой ничего бы не добавил.

Ошибки от сервера приходят одним форматом и разбираются в `ApiException`
с машинным кодом. По `user_type_mismatch` и `unauthorized` сессия
сбрасывается, и роутер сам уводит на вход.

## Что работает

* **С1 · оплата в магазине.** Лимит набирается на клавиатуре (быстрые
  суммы, проверка по балансу) → PIN → одноразовый QR. Код подписывается
  HMAC-SHA256 на `payment_secret` и **обновляется сам** каждые 30 секунд:
  сервер считает возраст по времени внутри nonce и допуска не даёт.
  Дальше касса набирает сумму и сканирует камерой. В пределах лимита
  деньги уходят у клиента и приходят мерчанту. Сверх лимита — отказ, и
  ничего не двигается. Код одноразовый: повтор ловится уникальным
  индексом на сервере.
* **С2 · перевод.** Сканер постоянного QR получателя → имя спрашивается
  у сервера (в самом коде его нет, чтобы нельзя было подменить) → сумма
  с проверкой по балансу → подтверждение → PIN → чек. Неверный PIN
  встряхивает точки и не проводит перевод.
* **Пополнение.** Код активации: 12 цифр группами по четыре. Номинал
  известен только после погашения — спрашивать его заранее нельзя, иначе
  коды можно было бы перебирать, не тратя. Второй путь — постоянный QR
  для агента.
* **Нет связи.** Экран показывает плашку и гасит действия, которым нужна
  сеть. Очереди отложенных операций нет: её нет и на бэкенде.
* **История.** Сегменты «Hemmesi · Gelen · Giden» и шторка фильтра
  (период, диапазон суммы) отбирают уже полученный список на устройстве;
  группировка по дням считается от текущей даты. У кассы — своя история.

**QR работает по-настоящему.** Коды генерируются как настоящие QR
(`qr_flutter`) и читаются камерой (`mobile_scanner`): касса наводит
телефон на экран клиента и списывает сумму. Содержимое кода —
`nurpay://pay?t=…&l=…` для одноразового и `nurpay://user?p=…&n=…` для
постоянного; чужой код отклоняется, просроченный гасится, использованный
не срабатывает второй раз. Где камеры нет — например в симуляторе — окно
сканера работает как кнопка и проигрывает ту же ветку.

Чего нет: системного share (вместо него копирование чека в буфер),
возвратов и офлайн-очереди — их нет в спецификации бэкенда.

## Навигация

Вкладки (Esasy · Taryh · Profil) живут в `StatefulShellRoute` — у каждой
свой стек и своё состояние, повторный тап по активной вкладке возвращает
её в начало. Оболочек две, по одной на роль; страж не пускает в чужие
вкладки и не пускает дальше входа, пока не создан PIN.

Сценарии — оплата, перевод, пополнение, чек, касса — открываются **поверх**
вкладок на корневом навигаторе. Поэтому у сценария свой стек с нормальным
«назад», а нижняя панель не мигает посреди оплаты. Экран результата
возвращает на вкладку через `go`, схлопывая стек сценария.

Экранов из макета, ставших состояниями, а не отдельными страницами:
офлайн-главный (8.1) — это главный без сети; пустая история (8.3) —
состояние списка; пустой поиск (8.4) — состояние экрана контактов; PIN
поверх лимита (10.1) — шторка, а не страница. Вариант главного со
speed-dial (2.2) не вошёл: каркас в макете описан через док.

## Движение

Анимация здесь не украшение, а способ показать связь между экранами.

* **Переходы стека** — свой `PageTransitionsBuilder` на всех платформах:
  новый экран приезжает справа и проявляется, старый уходит влево и
  притухает.
* **Вкладки** не подменяются кадром: ветки остаются живыми, активная
  проявляется (`BranchSwitcher`), под иконкой едет брендовая «таблетка».
* **Шторки** подъезжают снизу вместе с затемнением, диалоги подрастают из
  центра — это даёт сам маршрут, экранам об этом знать не нужно.
* **Отклик на касание** — `Pressable`: кнопки, клавиши, карточки и строки
  проседают под пальцем. Это главный источник ощущения отзывчивости.
* **Появление блоков** — `Entrance`: всплывают снизу лесенкой. Задержка
  встроена в кривую, а не в таймер, поэтому анимация всегда доигрывает.
* **Суммы** перетекают к новому значению (`AnimatedMoney`) — после
  операции баланс не перескакивает.
* **Сканер** ведёт луч только сверху вниз, растворяя его у краёв: на
  развороте нет рывка. При захвате кода уголки подтягиваются внутрь.

Шкала длительностей и кривых — в `core/ui_kit/motion/app_motion.dart`.

## Тема

Одно правило: **в UI цвета берутся только из
`Theme.of(context).colorScheme`**. Hex-значения живут в единственном
файле — `core/theme/app_palette.dart`.

| роль                 | схема                  | бренд             |
|----------------------|------------------------|-------------------|
| `AppRole.customer`   | `customerLight/Dark`   | синий `#004F94`   |
| `AppRole.merchant`   | `merchantLight/Dark`   | зелёный `#00583A` |

Схему задаёт оболочка роли через `RoleTheme`; сканер берёт тёмную схему
той же роли (`RoleTheme.dark`). Роли Material 3 переиспользованы под смысл
продукта:

| роль M3                | смысл в Nur Pay                                |
|------------------------|------------------------------------------------|
| `primary`              | бренд текущей роли                             |
| `secondary`            | успех, входящие деньги, статус «онлайн»        |
| `tertiary`             | ожидание, офлайн-очередь (янтарный)            |
| `error`                | отказ, превышение лимита, выход                |
| `surfaceContainerLow`  | фон экрана с оттенком бренда                   |
| `surfaceContainerHigh` | клавиши цифровой клавиатуры                    |
| `surfaceBright`        | приподнятая поверхность (белая или тёмная)     |
| `outline`              | текст-подсказка и неактивные иконки            |
| `outlineVariant`       | разделители и светлые границы                  |
| `inverseSurface`       | тёмный фон сканера                             |

Типографика — IBM Plex Sans и IBM Plex Mono, файлы в `assets/fonts`
(шрифты нужны офлайн, поэтому вшиты). Размеры масштабируются
`flutter_screenutil` от базы 402 × 874.

Пластика: крупные мягкие скругления (`AppRadius`), двухслойные тени
(`AppShadows` — короткая задаёт край, длинная высоту), брендовые
поверхности с градиентом и бликом вместо плоской заливки. Рамки остались
там, где нужна граница, а не там, где нужна глубина.

## Данные

`features/wallet/data` — единственное место, которое знает про HTTP:
`WalletRemoteDataSource` держит маршруты, `WalletRepositoryImpl`
превращает ответы в сущности. Экраны видят только интерфейс
`WalletRepository`.

Деньги — `Money`: целые теңңе (1 манат = 100), никакого `double`. Формат
(«1 240,00», «+120,00») и разбор набранного на клавиатуре живут там же.
`AmountEditor` и `DigitsEditor` держат правила ввода: одна запятая, два
знака после неё, длина кода.

Содержимое QR описано в `features/wallet/domain/entities/nur_pay_qr.dart`.
Постоянный код несёт только `public_qr_uuid`; платёжный — `user_id`,
`max_amount`, `nonce` (uuid v7) и подпись HMAC-SHA256 по канонической
строке `<user_id>.<max_amount>.<nonce>`. Формат обязан совпадать с
бэкендом побайтово, поэтому он зафиксирован в одном месте и проверяется
тестом с эталонным значением.

## UI-кит

`core/ui_kit/ui_kit.dart` — один импорт на все компоненты. Компоненты не
знают ни о данных, ни о навигации: только о теме.

Кнопки и поля · `AppButton` (filled / tonal / neutral / outlined /
brandOutlined / danger / text), `AppIconButton`, `AppTextField`,
`AppSearchField`, `PhoneField`, `DisplayField`, `RangeFields`,
`AppChoiceChip`, `AppPillButton`, `AppSegmentedControl`.

Деньги · `AmountText`, `AmountLabel`, `BalanceCard`, `RevenueCard`.

Ввод кодов · `NumericKeypad`, `PinDots`, `OtpField`, `Shake`.

QR · `QrView`, `QrBrandCard`, `QrOutlinedCard`, `QrGlyph`,
`ScannerFrame`, `CountdownBar`.

Списки и состояния · `TransactionTile`, `ContactTile`, `AppListRow`,
`AppListGroup`, `DetailList`, `SectionLabel`, `BlockTitle`, `AppCard`,
`AppSelectableCard`, `EmptyState`, `ResultGlyph`, `InfoBanner`,
`NoticeBox`, `AppStatusBadge`, `AppAvatar`.

Каркас · `AppScaffold`, `AppTopBar`, `AppLargeTitleBar`, `AppBottomNav`,
`AppFab`, `AppExtendedFab`, `SpeedDial`, `AppSheet`, `AppScrim`,
`BrandMark`, `BrandLockup`.

Движение · `Pressable`, `Entrance`, `AnimatedMoney`, `AppMotion`,
`AppPageTransitionsBuilder`, `AppOverlayTransition`.

Камера · `ScannerView` — картинка с камеры, затемнение с окном и рамка;
без камеры окно работает как кнопка.

`AppSheet` ставит заголовок по центру и умеет действие справа.
